# Agents.md — Search

Краткое руководство для AI-агентов, работающих над проектом **Search**.

---

## 1. Назначение проекта

SPA для поиска земельных участков через разговорный интерфейс с нейросетью. Пользователь пишет запрос в чат, агент подбирает варианты, которые отображаются как карточки объявлений. По клику на карточку открывается страница детальной информации.

---

## 2. Стек

- **React 18 + TypeScript** (strict, `noExplicitAny`)
- **Vite 6**
- **Tailwind CSS v4** (`@tailwindcss/vite`) — utility-first стили
- **styled-components** — динамические/тематические стили и компоненты-обёртки
- **react-router-dom v7**
- **zustand** — состояние
- **react-hook-form + zod** — формы и валидация
- **lucide-react** — иконки
- **motion** — анимации (установлен, но используется по необходимости)

---

## 3. Архитектура: Feature-Sliced Design v2.1

Слои (только нисходящие импорты):

```
app → pages → widgets → features → entities → shared
```

Слой `processes` не используется.

| Слой | Ответственность | Примеры |
|------|-----------------|---------|
| `app` | Инициализация, провайдеры, маршруты, глобальные стили | `App.tsx`, `AppRouter.tsx`, `AppProviders.tsx` |
| `pages` | Тонкие страницы, собирающие виджеты | `LoginPage`, `ChatPage`, `ListingDetailPage` |
| `widgets` | Самостоятельные блоки интерфейса | `ChatPanel`, `ListingsGrid`, `ListingDetail` |
| `features` | Пользовательские сценарии и действия | `auth`, `send-message`, `show-results` |
| `entities` | Предметная область: типы, сторы, UI-компоненты сущностей | `session`, `chat`, `listing` |
| `shared` | Переиспользуемый код: UI-kit, утилиты, конфиг | `Button`, `Input`, `cn`, `routes` |

### Правила FSD

- Каждый слайс публикует **только** публичное API через `index.ts`.
- Импорты между слайсами только через их `index.ts`.
- Импорты только сверху вниз: `pages` может импортировать `widgets`, но не наоборот.
- Внутри слайса сегменты: `ui`, `model`, `lib`, `api`, `config`.
- `app` и `shared` — это слайсы уровня слоя, без подпапок-слайсов.

## 4. Соглашения по коду

### 4.1. Язык

- Код, имена переменных, компонентов и типов — **английский**.
- Пользовательский текст в интерфейсе — **русский** (если не указано иное).
- Комментарии и документация — **русский**, если не требуется иное.

### 4.2. Импорты

- Используй алиас `@/` для всего из `src/`.
- UI-kit импортируй из `@/shared/ui`.
- Утилиты — из `@/shared/lib`.
- Конфиг — из `@/shared/config`.
- Сущности и фичи — только через их публичный `index.ts`.

Пример:

```tsx
import { Button, Input, Spinner } from '@/shared/ui';
import { cn, formatPrice } from '@/shared/lib';
import { routes } from '@/shared/config';
import { useAuthStore } from '@/entities/session';
import { LoginForm } from '@/features/auth';
```

### 4.3. Стили

- **Tailwind** — для раскладки, отступов, типографики, утилитарных классов.
- **styled-components** — для компонентов, которым нужны тематические токены, сложные hover/active состояния или динамические стили.
- Все дизайн-токены определены в `src/app/styles/theme.css` и зеркалятся в `src/app/styles/theme.ts`.
- В styled-components обращайся к теме через `${({ theme }) => theme.colors.primary}`.
- Для условных `className` используй `cn()` из `@/shared/lib`.

```tsx
import { cn } from '@/shared/lib';

<div className={cn('flex items-center', isActive && 'bg-primary')} />
```

### 4.4. UI-kit

- `Button` — основная кнопка. Поддерживает `variant` (`primary`, `secondary`, `ghost`), `size` (`sm`, `md`, `lg`), `isLoading`.
- `Input` — поле ввода.
- `Spinner` — индикатор загрузки.
- Не добавляй `as`/`polymorphic` пропсы в существующие компоненты без явной необходимости. Для ссылок используй `<a>` или оборачивай `Button` в `styled(Button).attrs({ as: 'a' })`.

### 4.5. Маршруты

- Все пути хранятся в `src/shared/config/routes.ts`.
- Используй константы, а не строки:

```tsx
import { routes } from '@/shared/config';

<Route path={routes.chat} element={<ChatPage />} />
<Link to={routes.listing.replace(':id', id)} />
```

### 4.6. Состояние

- Глобальное состояние — zustand-сторы в `entities/<name>/model/`.
- Локальное состояние виджета/фичи — `useState`/`useReducer` рядом с компонентом.

### 4.7. Формы

- Используй `react-hook-form` + `zod`.
- Схемы валидации живут в `features/<name>/model/`.
- Типы форм экспортируй из того же файла, что и схема.

### 4.8. Типы

- Запрещено использовать `any` — ESLint выдаст ошибку.
- Доменные типы живут в `entities/<name>/model/types.ts` и экспортируются через `index.ts`.

## 5. Рабочий процесс агента

1. **Прочитай** связанные файлы перед изменениями.
2. **Планируй** минимальные изменения, соответствующие запросу.
3. **Реализуй**, следуя существующим паттернам.
4. **Проверь**:
   - `npm run build` — должен проходить без ошибок TypeScript и Vite.
   - `npm run lint` — должен проходить без ошибок ESLint.
   - Если есть тесты — запусти их.
5. **Сообщи**, что изменилось, где и как прошла проверка.

## 7. Частые ловушки

- **Дублирующий импорт `styled-components`** — проверяй начало файла.
- **`Button as="a"`** — компонент `Button` не поддерживает полиморфный `as`. Используй `styled(Button).attrs({ as: 'a' })` или обычный `<a>`.
- **Импорт из внутренних файлов слайса** — всегда используй публичный `index.ts`.
- **Хардкод путей** — маршруты только из `routes`.
- **Смешение Tailwind и styled-components без нужды** — предпочитай Tailwind для простых случаев.
